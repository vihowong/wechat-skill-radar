# 对标档案：公众号「逛逛GitHub」

这份文件是对一个真实账号的**实测拆解**，不是感觉描述。所有数字来自 20 篇文章的正文 HTML 与 20 张封面原图，
用技能自带的 `scripts/style_probe.py` 抓取、解析、统计得出（口径与复现命令见第七节）。

**怎么用**：`wechat-layout.md` 定的是我们自己的版式（正文与编号已按这份档案升级）；
`visual-recipes.md` 的封面方案 B 也来自这里；写稿手感参考第五节，但**用词口径仍按 `writing-craft.md`**。

**想学另一个账号**：直接跑 `python style_probe.py all --seed "<该账号任意一篇文章的链接>"`，
它会产出 `_对标/<账号>/对标报告.md`，格式与本文同类。**别凭感觉说"它排版好看"**——先量。

**不学的部分先说清楚**：它的标题里有「堪称一绝」「玩疯了」「狠狠收藏」「太惊艳了」这类夸张词，
结尾有固定关注引导与公众号名片，正文里有「我实测」类第一人称体验。
这三类**一律不学**——`titles.md` 的标题党词表、`compliance.md` 的引导规范、
`writing-craft.md` 的「不伪造实测」是硬约束，优先级高于对标。**学结构、学排版、学图文比，不学它的词与自证。**

## 二、排版规格（可直接照抄的数值）

这是它最值得学的地方：**极简、极稳、一篇一变内容不变版式**。

### 正文

| 元素 | 实测值 |
| --- | --- |
| 正文字号 | **14px** |
| 行高 | **2em**（正文里出现 1328 次，唯一值） |
| 字距 | **0.034em** |
| 正文颜色 | `rgba(0, 0, 0, 0.9)` |
| 左右缩进 | `margin-left/right: 8px` |
| 段间距 | `margin-bottom: 16px` |
| 对齐 | `text-align: justify` |
| 字体栈 | `"PingFang SC", system-ui, -apple-system, "Helvetica Neue", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", Arial, sans-serif` |

**两个关键点**：

1. **字号 14px 配行高 2em**——字不大，但行距极宽。这是"透气感"的来源：手机上每屏信息量少，
   读者不会觉得密。比"字号大 + 行距紧"更耐读。
2. **段落只做 8px 缩进**——几乎顶格，不靠留白撑，靠行距和分段撑。

### 章节编号（它最标志性的视觉件）

| 属性 | 值 |
| --- | --- |
| 内容 | `01` `02` `03`（两位数字，无「第」「、」「.」） |
| 字号 | **32px**（是正文的 2.3 倍） |
| 字重 | 700 |
| 字体 | **Futura-Medium**（几何无衬线；落不到时退到系统字体也不难看） |
| 颜色 | **`rgb(255, 104, 39)`** —— 橙红，全篇唯一强调色 |
| 字距 | 1px |
| 位置 | 独立成段，在标题上方，上方 margin 24px |

编号是**大号 + 橙色 + 独占一行**，在小标题上方形成一条竖直节奏线。全篇只用这一个强调色。

### 小节标题

| 属性 | 值 |
| --- | --- |
| 字号 | **16px**（比正文 14px 只大 2px） |
| 字重 | bold |
| 颜色 | `rgba(0, 0, 0, 0.9)`（与正文同色） |
| 下间距 | `margin-bottom: 16px`（或 8px） |

**注意**：它的标题**不换色、不加线、不加底色**，只靠"大 2px + 加粗 + 前后留白"区分。
标题的辨识度来自**编号块**，不来自标题本身。这是很克制的做法。

### 颜色使用（全站统计）

| 颜色 | 出现次数 | 用途 |
| --- | --- | --- |
| `rgba(0, 0, 0, 0.9)` | 1696 | 正文与标题（唯一正文色） |
| `rgb(34, 34, 34)` | 108 | 少数段落的正文色 |
| `rgb(255, 104, 39)` | 107 | **章节编号（唯一强调色）** |
| `rgb(123, 12, 0)` / `rgb(61, 167, 66)` / `rgb(122, 79, 214)` | 43 / 21 / 21 | 从截图或引用里带进来的，不是版式色 |
| `rgb(178, 178, 178)` | 25 | 图注 / 次要小字 |

**结论**：版式色只有**黑 + 橙**两个。强调色严格只用一处（编号）。

## 三、结构骨架

### 篇幅与节数

| 项 | 中位 | 区间 |
| --- | --- | --- |
| 正文字数 | **2035 字** | 1362–5159 |
| 节数 | **3.5 节** | 3–21 |
| 图片数 | **12 张** | 4–37 |
| 图/千字 | **6.2 张** | — |

节数分布：**3 节最常见（10/20 篇）**，其次 4 节、5 节。20+ 节只出现在月度盘点（一篇 20 个项目）。

### 单节内部结构（固定四段式）

```
[01]                      ← 大号橙色编号，独占一段
小节标题                    ← 16px 加粗
（空行）
开头 2–4 句：这是什么、给谁用     ← 含一个术语解释
（空行）
中间 3–6 句：怎么用、能做什么、限制   ← 含一个具体场景
（空行）
结尾 2–4 句：补充细节、适用人群
开源地址：https://github.com/...    ← code/pre 块，固定格式
```

**每节末尾的地址行格式**（实测前缀分布）：

| 前缀 | 次数 |
| --- | --- |
| `开源地址：` | 102 |
| `地址：` | 21 |
| `项目地址：` | 11 |
| `开放平台：` / `项目官网：` / `在线试玩：` | 各 2 |

用 `<pre><code>` 包住，**不是**超链接文字。GitHub 链接占绝大多数。

### 段落节奏：一句一段

| 项 | 值 |
| --- | --- |
| 段落总数（20 篇） | 1244 |
| 段落字数中位 | **34 字** |
| 段落字数均值 | 36.6 字 |
| 80 字以内的段落 | **97.6%** |
| 最长段落 | 412 字（仅 1 处，是代码块被算进来的） |

**它几乎做到"一句话 = 一个段落"**。每段一个意思，段与段之间靠空行断开。
这是它读起来不累的根本原因，比任何修辞都有效。

### 首节与末节的不对称

从 20 篇的「每节文本段数」看，有一个稳定规律：

- **首节最长**（8–38 段）：要交代背景、术语、来源。
- **中间节均衡**（4–10 段）。
- **末节固定 3 段**：收尾 + 关注引导 + 引导说明。

## 四、配图体系

### 封面（20 张全部一致）

| 项 | 实测值 |
| --- | --- |
| 尺寸 | **1280×544**（2.35:1；实测 1280×543 / 544 / 545） |
| 体积 | 中位 **72KB**（区间 48–110KB，JPEG） |
| 平均亮度 | 83.5（中低） |
| 暗部占比 | **59.0%** |
| 亮部占比 | 18.7% |
| 底色 | 近纯黑（多张主色 `#141414`–`#181818`，占 26–43%） |

**版式公式（20 张无例外）**：

```
┌──────────────────────────────────────────┐
│                                          │
│   ┌─────────┐    ████████████████████    │  ← 第一行：超粗白色大字
│   │         │    ████████████████████    │
│   │  3D 主体 │                            │
│   │  （左侧） │    ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓    │  ← 末行：彩色实心色块 + 白字
│   │         │    ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓    │
│   └─────────┘                            │
└──────────────────────────────────────────┘
   左 40%：立体主体    右 60%：2–3 行文字
```

四条不可动摇的规则：

1. **纯黑底**，不是照片底。背景无纹理、无渐变、无网格（实测多张底色占比 26–43% 是单一近黑色）。
2. **左侧一个 3D 立体主体**（GitHub 猫、3D 图标、像素模型、卡通形象），占宽度约 40%，居中偏左。
   主体是**渲染感的立体物**，不是照片、不是扁平插画。
3. **右侧 2–3 行超粗白字**（字重 800–900，近似思源黑体 Heavy / 阿里巴巴普惠体 Heavy）。
   第一行常为纯白，末行换成**实心彩色矩形块 + 白色字**，色块与左侧主体呼应。
4. **每张只用一个彩色**（紫 / 蓝 / 橙红 / 红），跟着左侧主体的颜色走。

**色块配色实测样本**：紫 `#5B4BC4` 系、蓝 `#2563C9` 系、橙红 `#C05C1D` / `#D73E35` 系、绿松 `#1F332E` 系。

**它为什么有效**：列表页里封面只有拇指大。纯黑底 + 超粗白字 = 最高对比；左侧 3D 主体提供"质感钩子"；
末行彩色色块提供唯一一处颜色记忆点。三条在缩略图尺寸下都还在。

### 正文配图：证据类压倒一切

20 篇里正文图 202 张 PNG + 20 张 GIF，**几乎全是原始证据截图**，实测类型分布：

| 类型 | 占比 | 说明 |
| --- | --- | --- |
| **GitHub 仓库页 / README 头图** | 最多 | 带 star 数、badge、目录树，一眼证明"真有这个东西" |
| **官方产品界面截图** | 多 | 直接截官网/控制台，常带深色主题 |
| **X（Twitter）帖子截图** | 中 | 引用外部讨论，带作者头像与转发数 |
| **微信对话截图** | 中 | 展示自己用公众号后台问项目的效果 |
| **手绘风格流程图** | 少但显眼 | 白底 + 黑色火柴人 + 橙色箭头 + 手写体标注，解释工作原理 |
| **数据截图** | 少 | 榜单、Star History 曲线 |

**关键观察**：

1. **它不做信息图**。20 篇里没有一张用代码画的对照表、流程图、数据图。
   信息类内容一律用**截图**或**文字**表达。这和我们现有的"对照表用代码画"是两条路。
2. **图片宽度以 1080 为主**（140/202 张），其次是 894（21 张）。
3. **比例极不统一**：竖长图 132 张、超长图（比例 <0.5）49 张、方图 33 张、宽图 24 张。
   手机截图与网页长截图天然是竖的——**它不裁，直接放**。
4. **不标图注**。截图自带信息，加了反而啰嗦。
5. **不标来源**。这是它的风险点，我们**不学**——`compliance.md` 要求官方图注明来源、保留水印。

### 图文比

**6.2 张图 / 千字**。按 2035 字算，一篇约 12 张图。
换算成段落：**每 2–3 段就有一张图**。这是"滑得下去"的关键——读者几乎不用连续读超过 5 段。

## 五、写作手感

### 标题（20 条实测）

| 指标 | 值 |
| --- | --- |
| 汉字数 | 中位 **17.5 字**（区间 12–21） |
| 含 `GitHub` | 16/20 |
| 含具体数字 | 16/20 |
| 以「。」结尾 | **20/20** |
| 用「，」分两截 | 18/20 |
| 含「开源」 | 14/20 |

**主导句式**（占绝大多数）：

```
[具体数字/硬事实] ， [评价或悬念] 。
```

实测样本：

- `37K Star 的 GitHub 开源项目开放 AI 网关，10 人团队免费用。`
- `一周就收割 2 万 Star，这个 GitHub 项目把近期爆火的 Jev 模型开源了。`
- `GitHub 上狂揽 7500 星的 DeepSeek Harness 桌面端，推出企业版了。`
- `让 AI 帮你操作手机，这个 GitHub 开源项目支持安卓和 iPhone。`
- `5 个 GitHub 上开源的稀奇古怪小玩意儿，这一届网友真天才。`

**它的标题公式**：前半截给一个**可核对的硬数字或具体事实**（Star 数、时间、平台、数字），
后半截给一个**人味评价或悬念**。前面负责可信，后面负责想点。

**我们借的部分**：「硬事实 + 人味」这个两截结构，以及**句号收尾**（显得平静，不像标题党）。
**我们不借**：评价那一截里的夸张词（堪称一绝、玩疯了、太惊艳了、狠狠收藏）——换成具体结果或事实。

### 开篇（20 条实测）

两种开法，都很短（一句到两句）：

| 开法 | 样本 |
| --- | --- |
| **直接给事实** | `Jev 大模型刚发布，就在外网获得大量的讨论。`<br>`阶跃星辰发布了新一代旗舰模型： Step 5 Preview。`<br>`最近有一个 GitHub 项目，Star 数量涨的还挺猛的。` |
| **直接给结论/标题** | `给你的 Agent 赋予 CAD 超能力`<br>`把一群 AI Agent 管成一家公司`<br>`桌面太乱，拿块地毯盖住` |

**没有一篇用"随着……的发展"这类铺垫**。要么是"最近发生了什么"，要么是一句能当小标题的结论句。

### 句长与标点（20 篇，44667 字）

| 项 | 值 |
| --- | --- |
| 句长中位 | **34 字** |
| 句长均值 | 43.4 字 |
| 26–40 字的句子 | 最多（346/1007） |
| 破折号「——」 | **0 处** |
| 感叹号「！」 | 5 处（0.1‰） |
| 问号「？」 | 5 处（0.1‰） |
| 引号「」 | 2 处 |
| 逗号 | 25.1‰ |
| 句号 | 22.5‰ |

**它的标点极克制**：全站 4.4 万字里破折号 0 处、感叹号 5 处。
情绪不靠标点，靠**把事实摆出来**。这一点和我们 `writing-craft.md` 的标点约束完全一致，可以放心照抄。

### 人称

| 词 | 次数 |
| --- | --- |
| 你 | 146 |
| 它 | 121 |
| 我 | 46 |

**「你」是「我」的 3 倍**——写法是"你打开 XX，会看到 YY"，而不是"我打开了 XX"。
「我」主要出现在两处：作者自己做的项目（婚礼网页、Codex 用法），以及**它明确标注的实测**
（「比如我实测了一下，框选了美国白宫区域」）。

**这一条要分开看**：它敢写「我实测」是因为它真跑了并且贴了截图。
我们按 `writing-craft.md` 的口径——**没跑过就不写**；跑过要标「自测」并存进 `素材/资料与出处.md`。

### 高频表达（可借的语气件）

| 表达 | 用法 |
| --- | --- |
| `开源地址：` | 每节末尾的固定件 |
| `比如` | 引出具体例子（20 篇出现 9 次以上） |
| `可以` | 描述能力，不用"支持"堆砌（216 次） |
| `说白了` | **0 次**——它其实不怎么说口语垫词 |
| `其实` | 2 次 |

**意外发现**：它**几乎没有口语垫词**。不用"说白了""其实""讲真"。
它的"人味"来自**一句一段的节奏 + 具体场景 + 少量自嘲**，不来自口头禅。
这对我们是个提醒：**去 AI 腔不等于加口头禅**。

## 七、测量方法（可复现）

**用技能自带的 `scripts/style_probe.py` 就能重跑这套测量**，不必依赖任何一次性脚本：

```bash
# 1) 从一篇文章拿到账号标识与合集 id
python style_probe.py seed "https://mp.weixin.qq.com/s/xxxxxxxx"

# 2) 抓文章列表（合集分页）
python style_probe.py index --name 逛逛GitHub --biz MzUxNjg4NDEzNA== \
    --album 1339316622149992449 --max 20

# 3) 抓正文（列表接口被限流时，可用 --urls 直接给文章链接）
python style_probe.py fetch --name 逛逛GitHub --max 20

# 4) 出版式报告 → _对标/逛逛GitHub/对标报告.md
python style_probe.py report --name 逛逛GitHub
```

它输出的数字与本文一致（同一套判定口径）：

| 项 | 报告里的值 |

**两个最容易踩的坑**（探针里已经处理，手写脚本时会遇到）：

1. **字号要取"最终生效"的那一层。** 微信编辑器给每段套一层外层 `span`（默认 17px），
   作者手动改过的字号在更内层的 `textstyle` span 里。只统计外层会把 14px 误判成 17px。
   探针的判定是：有 `textstyle` span 就用它，否则退回外层。
2. **合集分页的 `begin_itemidx` 必须是 1。** 传 0 时接口返回 200 但只有 `base_info`、没有 `article_list`
   （看起来像"限流"，其实是参数不对）。另外微信会真的限流——返回 200 但 body 只有 170 字节，
   这时要退避重试，别把它当成"这个账号没有文章"。
