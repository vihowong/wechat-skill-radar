# 发布前自检清单

`scripts/qa.py` 负责机器能查的部分，必须跑到 **0 FAIL** 才交付；WARN 要逐条看过再决定改不改。
下面四部分都要过：机器项、图、文、版权与合规。

## 一、机器检查（qa.py）

```bash
python _工作文件/qa.py 发布稿.md 公众号粘贴版.html
```

- 无禁用元素：账号标识、旧版式残留、往期推荐、公众号名片、外链联系方式。
- 正文段落长度：最长 ≤110 字（安装命令行不计入）。
- 配图：比例（`strict` / `loose` 由 `qa_config.json` 决定）、无缺失、总体积达标。
- 必备模块：导语、结语、免责声明齐全。
- 内联样式已注入（15px / 行高 1.75 / 字距 0.02em）；文字颜色只用白名单。
- 标题候选：元信息里 ≥6 条候选、有「推荐标题」、推荐标题 ≤20 字、无标题党词。
- AI 腔：无硬禁用词；慎用词不超阈值；破折号与感叹号不超频；同一字段不连着用「——」接续。
- 节奏：没有连续三段字数接近；段落起句没有反复用同一个开头。
- **违规词与极限词**：`compliance_hard` 列表里的词 0 命中；`compliance_soft` 的命中逐条看过（带上下文）。
- **素材授权**：用到 `素材/图库/` 的图片时，`素材/图库/图片来源.md` 必须存在，且每张图都能查到记录。
- **敏感场景边界句**：涉及投资、医疗、法律等话题时，文末要有对应的"不构成建议"表述。

## 二、目视检查

**图**

- 封面两张都看过：1:1 的标题、徽标、底部信息栏互不遮挡。
- 每张配图都放大看过：有没有文字被裁、图形互相压住、箭头没渲染、发光把线吃掉。
- 照片底图：压暗够不够（标题一眼能读）、有没有和标题打架的文字物体（招牌、路牌、屏幕上的字）。
- 照片页面是 `.jpg`；体积在预算内。
- 截图：红框标在关键位置上；打码了头像、昵称、邮箱、密钥；没有裁掉原作者署名。
- 配图内容与正文一致：图里出现的项目名、数字和正文对得上；**截图里的数字要抽样回原文核对一遍**。

**文**

- 每个项目的字段名、顺序、语气完全一致。
- 星标数、安装命令能对上当期抓取结果与 README。
- 实测数据（耗时、成本、成功率）能在 `素材/实测记录.md` 里找到出处，测试条件写清楚了。
- 长 URL 在手机宽度下不会撑宽版面。
- 结语 → 免责声明 → 平台引导三段齐全；没有往期推荐与名片。
- 敏感场景（投资、医疗、法务）写清边界与免责。

**标题（按 `titles.md` 过一遍）**

- 候选 6–8 条，覆盖 4 种以上钩子类型；没有两条是同一句式的换词。
- 推荐标题 ≤20 个汉字，扫一眼能说出"给谁看"；数字与正文一致；无极限词。
- 推荐标题和封面主标题不写同一句话（一个讲身份或事实，一个讲能拿到什么）。
- 把标题 + 封面第一行连起来念一遍，像人话。

**写法与留存（按 `writing-craft.md` 过一遍）**

- 实测证据够三处吗？全是转述的话，开头有没有告诉读者这是资料整理？
- 前 100 字说清了：写给谁、读完能拿到什么。
- 每节开头有一句"这节看什么"，不是直接从字段块开始。
- 失败点写了几处？一处都没写，读者会当成软文。
- 通读一遍，把"换个主题也能用"的段落删掉；连续两句都在形容的地方换成事实。
- 段与段之间有长短变化；没有任何一段是为了凑字数写的。
- 结尾点名了"先装哪个 / 先看哪个"，并给了一句边界提醒。

**版式**

- 浏览器打开 `公众号粘贴版.html`，复制范围外的预览外壳没有被带进去。
- 粘进公众号编辑器后检查一次：标题层级、图片圆角与描边、图注居中、来源小字、尾部小字。

## 三、版权与合规（按 `compliance.md` 过一遍）

- 引用他人观点是短引用（单处 ≤100 字、全篇 ≤10%）并写明了来源与作者。
- 没有整段搬运 README、他人文章、付费内容。
- 用到的项目许可证看得懂：GPL 只做介绍、没有 LICENSE 的不复制代码与文档。
- 图库素材是可商用授权（CC0 / 公共领域 / CC-BY / CC-BY-SA / Pexels / Unsplash），没有用 NC / ND。
- CC-BY、CC-BY-SA 的图片已按格式署名；Pexels / Unsplash 也留了记录。
- 没有出现政治敏感、赌博色情、破解外挂、翻墙工具、AI 换脸等内容，也没有配合这些的软性表述。
- 没有出现他人隐私信息与未成年人可识别信息。
- 当期用了 AI 生图或大量 AI 起草时，已补标识并在发布时勾选平台的对应选项。
- 数据都标了日期与来源，写明是快照；"免费"这类说法确认过当期仍然成立。

## 四、交付时向用户汇报

1. 文章路径（`发布稿.md`、`公众号粘贴版.html`、封面、配图、预览）。
2. 本期**形态与主题**，以及收录清单：项目名 + 星标 + 一行它替你做什么。
3. **推荐标题 + 备选标题**（含推荐理由），让用户直接挑一个用。
4. **实测做了什么**：跑了几个、耗时多少、发现了哪些失败点（没跑成的说明原因）。
5. **素材与授权**：图库来自哪、许可是什么、有没有需要署名的地方。
6. **这期在结构或视觉上换了什么做法**——这是"不要千篇一律"这条规则的验收项。
7. 数据口径：抓取日期与来源；本期是否有值得读者注意的空白方向。
