# 发布前自检清单

`scripts/qa.py` 负责机器能查的部分，必须跑到 **0 FAIL** 才交付。下面两项都要过。

## 一、机器检查（qa.py）

```bash
python _工作文件/qa.py 发布稿.md 公众号粘贴版.html
```

- 无禁用元素：账号标识、旧版式残留、往期推荐、公众号名片。
- 正文段落长度：平均不过长、最长 ≤110 字（安装命令行不计入）。
- 配图：比例一致、无缺失、总体积 ≤3MB。
- 必备模块：导语、结语、免责声明齐全。
- 内联样式已注入（15px / 行高 1.75 / 字距 0.02em）。
- 文字颜色只出现白名单里的值。
- 标题候选：元信息里 ≥6 条候选、有「推荐标题」、推荐标题 ≤20 字、无标题党词。
- AI 腔：无硬禁用词；慎用词不超过阈值；破折号与感叹号不超频；同一字段不连着用「——」接续。
- 节奏：没有连续三段字数接近的情况；段落起句没有反复用同一个开头。

## 二、目视检查（人工）

**图**

- 封面两张都看过：1:1 的标题、徽标、底部信息栏互不遮挡。
- 每张配图都放大看过：有没有文字被裁、图形互相压住、箭头没渲染、发光把线吃掉。
- 配图内容与正文一致：图里出现的仓库名、数字和正文对得上。

**文**

- 每个技能的字段名、顺序、语气完全一致。
- 星标数、安装命令能对上当期抓取结果与 README。
- 长 URL 在手机宽度下不会撑宽版面。
- 结语 → 免责声明 → 平台引导三段齐全；没有往期推荐与名片。
- 敏感场景（投资、医疗、法务）写清边界与免责。

**标题（按 `titles.md` 过一遍）**

- 候选 6–8 条，覆盖 4 种以上钩子类型；没有两条是同一句式的换词。
- 推荐标题 ≤20 个汉字，扫一眼能说出"给谁看"；数字与正文一致。
- 推荐标题和封面主标题不写同一句话（一个讲身份，一个讲能拿到什么）。
- 把标题 + 封面第一行连起来念一遍，像人话。

**去 AI 腔与留存（按 `writing-craft.md` 过一遍）**

- 前 100 字说清了：写给谁、读完能拿到什么。
- 每节开头有一句"这节看什么"，不是直接从字段块开始。
- 每个技能至少一个读者能对号入座的场景；只有功能清单的条目不算写完。
- 通读一遍，把"换个行业也能用"的段落删掉；连续两句都在形容的地方换成事实。
- 段与段之间有长短变化；没有任何一段是为了凑字数写的。
- 结尾点名了"先装哪个"，并给了一句边界提醒。

**版式**

- 浏览器打开 `公众号粘贴版.html`，复制范围外的预览外壳没有被带进去。
- 粘进公众号编辑器后检查一次：标题层级、图片圆角与描边、图注居中、尾部小字。

## 三、交付时向用户汇报

1. 文章路径（`发布稿.md`、`公众号粘贴版.html`、封面、配图、预览）。
2. 当期收录清单：仓库名 + 星标 + 一行它替你做什么。
3. **推荐标题 + 备选标题**（含推荐理由），让用户直接挑一个用。
4. **这期在结构或视觉上换了什么做法**——这是"不要千篇一律"这条规则的验收项。
5. 数据口径：抓取日期与来源；本期是否有需要读者注意的空白方向。
