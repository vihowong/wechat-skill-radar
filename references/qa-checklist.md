# 发布前自检清单

`scripts/qa.py` 负责机器能查的部分，必须跑到 **0 FAIL** 才交付。下面两项都要过。

## 一、机器检查（qa.py）

```bash
python _工作文件/qa.py 发布稿.md 公众号粘贴版.html
```

- 无禁用元素：账号标识、旧版式残留、往期推荐、公众号名片。
- 正文段落长度：平均不过长、最长 ≤110 字（安装命令行不计入）。
- 配图：比例一致、无缺失、总体积 ≤3MB。
- 必备模块：导语、结语、免责声明齐全。
- 内联样式已注入（15px / 行高 1.75 / 字距 0.02em）。
- 文字颜色只出现白名单里的值。

## 二、目视检查（人工）

**图**

- 封面两张都看过：1:1 的标题、徽标、底部信息栏互不遮挡。
- 每张配图都放大看过：有没有文字被裁、图形互相压住、箭头没渲染、发光把线吃掉。
- 配图内容与正文一致：图里出现的仓库名、数字和正文对得上。

**文**

- 每个技能的字段名、顺序、语气完全一致。
- 星标数、安装命令能对上当期抓取结果与 README。
- 长 URL 在手机宽度下不会撑宽版面。
- 结语 → 免责声明 → 平台引导三段齐全；没有往期推荐与名片。
- 敏感场景（投资、医疗、法务）写清边界与免责。

**版式**

- 浏览器打开 `公众号粘贴版.html`，复制范围外的预览外壳没有被带进去。
- 粘进公众号编辑器后检查一次：标题层级、图片圆角与描边、图注居中、尾部小字。

## 三、交付时向用户汇报

1. 文章路径（`发布稿.md`、`公众号粘贴版.html`、封面、配图、预览）。
2. 当期收录清单：仓库名 + 星标 + 一行它替你做什么。
3. **这期在结构或视觉上换了什么做法**——这是"不要千篇一律"这条规则的验收项。
4. 数据口径：抓取日期与来源；本期是否有需要读者注意的空白方向。
