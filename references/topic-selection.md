# 选题：一期一个行业

这份文件管「这一期写谁」。抓取、成稿、出图的规则在另外几个文件里。

## 一、硬性口径

- **每期只写一个行业。** 正文里出现的技能必须全部属于这个行业——哪怕旁边那个技能星标更高、更热，也不能塞进来。
- **判定标准只有一条**：读者扫一眼标题和封面，能立刻说出「这篇是给谁看的」。说不出来，就说明行业没定住。
- 行业不只指传统行业。来源行业（金融、医疗、法律、教育、电商、制造、物流……）和职能行业（设计、写作、营销、人力、科研、运维、编程……）都算，选哪个由当期读者决定。
- 跨行业的素材**只允许出现在结语里，且只有一句**，用来对比「这个行业现在空在哪」。不要写成条目。
- 行业要写进**项目文件夹名**和**稿件元信息**（例：`2026-10-01_金融热门Skill清单`）。

## 二、行业与抓取参数对照

| 行业 | 抓取参数 | 说明 |
| --- | --- | --- |
| 金融 / 营销 / 出海贸易 | `--set finance` / `--set marketing` / `--set trade` | 这三套是按细分职能拆过的关键词表，命中更准、同质化更少 |
| 设计 / 写作 / 办公文档 / 表格数据 / 科研 / 法律 / 视频音频 / 编程 / 电商 / 人力 / 图表可视化 | `--set general` | 一次抓 16 类，再用 `pick_skills.py <行业>` 过滤出本期要的那一类 |
| 上面都没有的行业 | 改 `github_skill_crawler.py` 里的 `INDUSTRY_QUERIES` | 加一条，形如 `"医疗": "skill medical health in:name,description"`，键名就是文章里的行业名 |

## 三、入选标准（每期 8–10 个）

按顺序过筛，不符合的直接换下一个：

1. **属于本期行业**：仓库名、描述或 README 里能看出它是为这个行业做的。
2. **实用价值高**：读者装完能在一件**真实、反复发生**的活上省时间。只能做演示、交不出东西的，降级或不用。
3. **上手简单**：优先「一条命令装完」（●○○），其次「装完选一次配置」（●●○）。要装环境或配密钥的（●●●）**一期最多 2–3 个**，并且要在字段里写明缺什么。
4. **近期仍活跃**：`pushed_at` 在 45 天内（crawler 已按此过滤）；星标与描述都取当期快照。
5. **未收录过**：跟这条内容线已发的文章去重（用 `pick_skills.py --covered`）。
6. **数据抄得到**：仓库名、星标、安装命令、功能描述都能从 README 或 GitHub 页面原文抄到；抄不到的不用。

## 四、「容易上手」要写到什么程度

每个技能必须能回答三件事：

- **装它要多久**：一条命令，还是要先备环境。
- **装完第一步干什么**：给一句可以照着念的话（例：「说一句『用 Distilly 给某人建一份 Person Profile』」）。
- **什么人不用装**：把不适用的人挡在外面，比多夸一句更有用。

命令照抄 README；README 给了多种装法时选最短的一条，把前提（Node / Python / 密钥 / 平台账号）写进同一个字段。门槛分级沿用：**●○○** 当天能用 / **●●○** 要选配置或备材料 / **●●●** 要装环境或配密钥。

## 五、行业轮换与去重

- **相邻两期不写同一个行业。** 选题前先看一眼历史项目文件夹名，确认上一期写的是什么。
- 建议在内容线根目录维护一份 `_已做行业.md`：一行一期，写「日期 + 行业 + 收录仓库」。没有这份文件时，就用文件夹名加各期的 `_pick.py` 兜底。
- 同一个仓库**不重复收录**，哪怕它又涨了星标；真需要再提，只能在结语里一句话带过。

## 六、这个行业捞不到足够的技能怎么办

- **8–10 个最好，5–7 个可以出**：结语里写清「这个行业刚起步，现在是入场时间」，把数量少当成信息，而不是缺陷。
- **少于 5 个就停下**：说明原因，写清搜了哪些关键词、最高星标是多少、哪些分类被限流，不要跨行业凑数、也不要拿非技能类项目（纯清单、桌面应用、数据集）充数。
- 放宽到「相邻行业」要谨慎：宁可这一期短，也不要把两期合成一期——读者判断不出这篇是给谁看的，选题就失败了。
