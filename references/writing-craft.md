# 写作手感：实测派怎么写，去 AI 腔，让人读到结尾

这份文件管「同样的信息，怎么写成有人愿意从头读到尾的样子」。对标账号（阿川同学这类实测向的 AI 技术号）的写法拆解在第一、四节，第五、六节是机器能拦的硬约束，结构设计见 `editorial-rules.md`，标题见 `titles.md`，版权与红线见 `compliance.md`。

## 一、基调：写你做过的事，不写你查到的结论

对标账号（实测向的技术号）最值钱的地方不是文笔，是**文章里有一半内容只能由做过的人写出来**。它的通篇骨架是：

1. 开头两句交代"我最近在测什么"，第三句就进正题。没有行业大势铺垫。
2. 中间按测试维度分节。每节先给任务设计，再给口径明确的数字，再给截图。
3. 专门留一节写它不行的地方，对手做得更好的地方也照写。
4. 结尾给"什么场景选它、什么场景别选"，落到具体选择上。

写的时候刻意往这三个方向使劲：

- **只有作者写得出的句子**：「我把 PPT 里的 4 张图、22 个数据，对着 Excel 挨个核对了一遍」——这种句子读者抄不走。
- **带口径的数字**：「2 小时 00 分 41 秒」，不是「两个多小时」；「190 个公式，0 错误」，不是「基本没问题」。
- **坦白的取舍**：「把原因说明白了，也不代表这一步就做完整了」——承认一处问题，比夸十句都涨信任。

反过来说，这几类句子一律删：把 README 的功能列表翻译一遍、把官方介绍换词重写、整段只有形容词，以及换个主题照样成立的段落（比如"AI 正在改变我们的工作方式"）。

## 二、一手证据链：每篇至少三处「我做过」

推荐稿和实测稿的区别就在这三处。写完先数一遍，不够三处就补：

| 证据类型 | 怎么写 | 例子 |
| --- | --- | --- |
| **我装过 / 跑过** | 装的时候卡在哪、跑的是哪个任务、崩没崩 | 「按命令装完 40 秒，第一次跑提示要先配密钥」 |
| **我数过 / 对过** | 自己统计出来的数字，注明口径 | 「六轮任务我记了耗时，最长一轮 41 秒」 |
| **我花过成本** | 时间、额度、积分、订阅价，写清单位 | 「跑完花了 804 积分，大约是同类的一半」 |

凑不出三处实测，说明这篇还不该发——要么换选题，要么把定位从"推荐"降级成"资料整理"，并在开头就告诉读者这是资料整理。

三种语气必须分开，混在一起就是编：

- **实测**：我今天装的、跑出来的、看到的。
- **转述**：README 里写着、作者说、文档里提到。用「作者称」「README 里写」标明。
- **判断**：我认为它适合谁。用「我觉得」「如果你的活是……」引出，不要写成事实。

## 三、实测稿怎么组织（单项目深挖必备）

1. **先给测试设计，再给结果。** 「四份材料、六轮任务」这种可复现的设计，比结论先说话更可信；读者能判断你的结论有多硬。
2. **失败点单独成节。** 不要散落在夸奖里，会像欲扬先抑；集中写，小标题直接写它做不到什么。
3. **过程里的小发现最值钱。** 比如它做完还自己回头复检、把错误整理成勘误表、上一轮的结论下一轮还敢复核——这类细节写出来，比"能力很强"有力。
4. **对比要给名字和数字。** 说"比别的好"没用；指出对方表格里写着 19.24%、正文里却写成未披露，读者才服。
5. **截图即证据，紧跟结论。** 讲完一句结论，下一行就是那张图；图注只写一句话，不重复正文。
6. **结尾落到选择上。** 「任务复杂、要来回改文件就选它；任务急着先出结果，用那个跑得快的」，让读者能当场做决定。

## 四、三种形态怎么落笔（蒸馏自对标账号）

对标账号是公众号「阿川同学」（AI / 科技实测向，固定开场、`01/02` 分节、截图即证据，一篇三千字上下配十几到二十几张图）。
它有三种成稿形态，各有各的落笔习惯。学它的做法，不学它的用词。

| 形态 | 怎么分节 | 每节干什么 | 语气装置 |
| --- | --- | --- | --- |
| **工具实测 / 教程** | `01` `02` `03` | 一个功能一节；操作一步一张截图，紧跟一句主观评价 | 「说白了就是还没被广告污染」「这一点还是挺细心的」「局限性有点强，期待以后能改」 |
| **能力横评** | `一、` `二、` … `七、` | 一节一个测试维度：任务设计 → 结果数字 → 截图 → 对照对象的表现 | 先给可复现的设计再给结论；「换成我，看到 0 错误大概率就准备交差了」 |
| **热点总结** | `01` `02` `03` | 一节一项更新：一句话说它是什么 → 怎么用（截图）→ 对我们的工作有什么用 | 「废话不多说，我们直接进入正文」；随口一句吐槽，但只针对现象不针对人 |

三种形态共用的部件：

1. **固定开场，三到五行**：期数 / 作者 / 首发 / 一句自我介绍 → 两句背景 → 一句"这篇讲什么" → 进入正文。
   我们把期数写进元信息与正文开头，方便读者追更；**但不写直播引导、加群引导、关注后领取**（合规，见 `compliance.md`）。
2. **开头就交差异化钩子**：直接说"它让我好奇的地方是……"，不要留到结尾才揭晓。读者是滑着看的。
3. **每节收一句人话**：「持续两个字才是它最有意思的地方」——把技术描述翻译成普通人的感受。
4. **结尾落到选择**：什么任务选它、什么任务别选、成本多少。不要说"让我们一起期待"。
5. **缺点集中写**，不要散在夸奖里；对手做得更好的地方也照写。
6. **互动只留在平台内**：「想看更多玩法可以评论区留言」可以；「加群」「私信领取」不行。

**不学的部分**：标题里的夸张词（王炸、炸裂、低调使用、绝了）、成串的感叹号、"绝对没有错"这类说法。
学结构、学证据链、学语气，用词按我们自己的口径走（`qa.py` 会拦）。

## 五、机器会拦的（`scripts/qa.py` 检查）

**硬禁用词**（出现即 FAIL，就地换成人话）：

赋能 · 抓手 · 闭环 · 生态位 · 全方位 · 一站式 · 在当今 · 随着…的发展 · 综上所述 · 总而言之 ·
众所周知 · 不难看出 · 值得注意的是 · 让我们 · 接下来 · 不可否认 · 显而易见 · 极大地 · 大大提升 ·
助力 · 打造生态 · 深度赋能

**慎用词**（全篇合计出现超过 2 次就报警）：

其实 · 非常 · 极其 · 深度 · 重磅 · 堪称 · 海量 · 强大 · 完美 · 极致 · 无与伦比

**标点**：

- 破折号「——」全篇 ≤8 处，且**同一个字段里最多 3 条**用「——」接续：连着四条都以「字段：……——……」开头，是最扎眼的模板痕迹。
- 感叹号 ≤2 处。想要"有力"，用事实和数字，不用标点。
- 引号统一「」；正文与图注都不放 emoji。

违规词、极限词（"最""第一""100%"这类）和敏感话题不在这一节，见 `compliance.md`，`qa.py` 会一起查。

## 六、句式黑名单

1. **三段排比**：「第一…第二…第三…」「首先…其次…最后…」——读者一眼看出是模板。
2. **「不是 A，而是 B」** 全篇最多一次。
3. **每段同一个收尾**：每条都以"适合…的人"结尾，读三条就腻。
4. **空话开头**：「随着 AI 的快速发展」「在这个信息爆炸的时代」——删掉不损失任何信息。
5. **名词化**：把"进行安装"写成"装"，把"实现效率提升"写成"快了 3 倍"。
6. **形容词堆叠**：连续两句只有评价没有事实，就把其中一句换成数字或命令。
7. **无主语的客观体**：「可以看出，该工具在处理长文档时表现优异」——换成「我把 200 页的年报扔进去，它在第 167 页的附注里把那个数字翻了出来」。

## 七、写出人味的具体做法

- **抽象换具体**：不写"存在兼容性问题"，写"剪映 5.9 之后自动导出会卡在弹窗上"。
- **敢写短句**：4–10 字的短句独立成段用来换气，每节最多一两处。
- **敢有态度**：一句轻吐槽、一句自嘲都行（"换成我，看到 0 错误就准备交差了"），但不阴阳竞品、不下行业判决。
- **每个项目至少一个场景**：谁、在什么情况下会用到它。只有功能清单的条目说服力为零。
- **抄一手细节**：README 原话、作者的实测数字、明确写出的"做不到什么"。
- **写取舍**："什么人不用装"要写到读者能对号入座，比再夸一遍有用得多。
- **保留不确定**：拿不准的写"据 README""作者说"，不要替作者下结论。
- **数字要能对账**：正文里的星标、耗时、价格，必须能在稿末的数据来源里找到出处。

## 八、把人留到结尾的结构

1. **前 100 字给答案**：这段写给谁看、读完能拿到什么、大概几分钟。别用行业大势铺垫。
2. **每节先给一句"这节看什么"**：先给结论或场景，再进条目。
3. **用桥句，不用悬念**：读者是滑着看的，"后面会讲到"会让人直接退出；直接说下一节是什么。
4. **每 2–3 段给一个可核对的东西**：星标、命令、数字、项目名、作者原话、实测耗时。
5. **长短句交替**：连续三段长度接近就拆一段——机器会拦，见 `qa.py` 的节奏检查。
6. **结尾点名**：说清楚"先装哪个 / 先看哪个"，再补一句边界提醒；不要"让我们一起期待"这类空号召。

## 九、交稿前逐条自问

- 实测证据够三处吗？全是转述的话，开头有没有告诉读者这是资料整理？
- 有没有哪一段换个主题也能用？删。
- 遮住项目名，读者还能说出它替谁干活吗？
- 有没有连续两句都在形容、没有事实？改掉一句。
- 读完前 100 字，读者知道继续读能拿到什么吗？
- 失败点写了几处？一处都没写，读者会当成软文。
- 有没有为凑字数写的内容？删掉之后文章更好还是更差。

这份清单也是 `qa-checklist.md` 目视项的一部分：机器查得到的（禁用词、标点频次、段落节奏、违规词）由 `qa.py` 拦，查不到的（空话、场景、桥句、证据链）靠这一节逐条过。
