# 公众号排版规格

这套规格已经定稿并验收过，**每期直接沿用**：版式稳定，内容换新。实现见 `scripts/md2wechat.py`。

> 正文的行高 2em / 字距 0.034em / 左右 8px 缩进，以及「大号单色编号独占一行」的章节件，
> 取自对标账号「逛逛GitHub」的实测规格（20 篇文章解析，见 `benchmark-guangguang-github.md`）。
> 强调色仍用本账号的墨绿，**没有**照抄它的橙色。

## 一、正文与标题

| 元素 | 规格 |
| --- | --- |
| 正文 | `font-size: 15px; line-height: 2em; letter-spacing: 0.034em; color: #1F2937; margin: 0 8px 16px; text-align: justify;` |
| 导语 | 外层 `<section style="background-color: #F8FAFC; border-radius: 10px; padding: 16px 18px; margin: 0 0 24px;">`，内文 15px / 行高 1.8 / `#374151` |
| **章节编号**（`## 01 标题`） | `font-size: 28px; font-weight: 700; color: #0E7C66; line-height: 1.2; letter-spacing: 1px; margin: 24px 8px 0;` |
| 一级小标题（无编号的 `##`） | 19px / 700 / `#0F172A`，`border-left: 4px solid #0E7C66; padding-left: 10px;` |
| 技能小标题（`###`） | 16px / 700 / `#0F172A`，纯文字，不加色块与标记 |
| 强调（`**…**`） | 只用墨绿 `#0E7C66`，全篇一个强调色 |
| 行内命令（`` `…` ``） | 等宽 + 浅灰底，让"能照抄的东西"一眼认出来：`font-family: Consolas, Menlo, monospace; font-size: 0.92em; color: #0F172A; background-color: #F1F5F9; padding: 1px 5px; border-radius: 4px;` |
| 列表 | `<ul style="margin: 0 0 18px; padding-left: 1.2em;">`，`li` 15px / 行高 2em / `#1F2937` / `margin: 0 0 8px` |
| 表格（选型指南的对比表） | 13px / 行高 1.7；表头浅灰底 `#F1F5F9` + 2px 下边框，单元格 1px `#E2E8F0` 下边框；**不用外边框、不用 `table-layout:fixed`** |
| 小字（图注） | 13px / 行高 1.7 / `#6B7280` / 居中 / `margin: 0 0 22px` |
| 尾部（免责声明 + 平台引导） | 13px / 行高 1.9 / `#6B7280`；免责三行 `margin: 0 0 3px`、引导一行 `margin: 0` |

### 章节编号：怎么用

在 Markdown 里把小标题写成 `## 01 它是什么`，转换器会自动渲染成
**大号墨绿编号独占一行 + 加粗标题**（编号与标题同色，辨识度来自编号本身，不来自标题）。

```
## 01 编剧：先把选题定下来
## 02 剪辑：把素材拼起来
```

- 编号一律**两位数字**（`01` 而不是 `1`），从 `01` 连续排下去，`qa.py` 会查连续性。
- 用了编号就**整篇统一用**，不要一半编号一半不编号。
- 编号是整篇唯一的"大号彩色元素"，别再给标题加底色或第二个颜色。
- 不想用编号的框架（如科普解读的 `一、二、`）就写普通 `##`，走左侧竖条样式。

### 行内命令：把"能照抄的东西"标出来

正文里出现的命令、参数、文件名，用反引号包起来：`` 装它：`npx skills add owner/repo` ``。
转换器会渲染成**等宽字体 + 浅灰底**的小块，在一段中文里一眼就能认出来。

这是"每篇至少给一个能落地的东西"这条规则的**视觉落点**：读者扫的时候先看到这些小块，
就知道这篇有能直接抄走的东西。别让命令混在普通文字里当句子读。

### 表格：选型指南的对比表直接写 Markdown

选型指南的必答项是"一张对比表"，**直接用 Markdown 表格**，转换器会渲染成公众号可粘贴的
`<table>`（全部内联样式）。不要为了放表格而把对比表做成图片——表里的数字应该是可复制、可核对的文本。

```
| 候选 | 上手门槛 | 价格 / 额度 | 最适合的活 |
| --- | --- | --- | --- |
| A 项目 | ●○○ 一条命令 | 以官网为准 | 先出草稿 |
| B 项目 | ●●○ 要配密钥 | 按量计费 | 要求稳 |
```

- **列数压到 4 列以内**。手机宽度只有 375px，5 列时每列不到 90px，中文会折成两三个字一行
  （转换器会打印提示，但不会拦你）。
- 维度多的时候改成**两列**：左边写维度名、右边写说明，比硬塞六列好读得多。
- 表里的每个数字都要能在 `素材/资料与出处.md` 里找到出处，并标明抓取日期。

### 行高 2em 意味着什么

字不大（15px）但行距很宽——这是"透气感"的来源。副作用与对策：

- **同样的字数，篇幅视觉上更长**：一篇 2000 字的稿子滚动距离明显增加，所以更要靠配图和小标题
  给读者"落点"（见第五节图文比）。
- **别再用 `<br>` 手动加空行**：行高已经 2em，手动空行会变成双倍间距，版面会散。
- **段落之间靠 `margin: 16px` 分开**，不要靠空段落。

## 二、图片

```html
<section style="text-align: center; margin: 0 0 8px;">
  <img src="配图/配图1_xxx.png" alt="图注文字"
       style="width: 100%; height: auto; display: block; border-radius: 10px; border: 1px solid #E2E8F0;">
</section>
<p style="font-size: 13px; line-height: 1.7; color: #6B7280; margin: 0 0 22px; text-align: center;">图注：…</p>
```

- **图注可以省略**：Markdown 里写 `![](配图/配图1_xxx.png)` 就只出图、不出一行图注，图片下面留 22px 间距。
  官方截图与界面图推荐这么用——截图自明，写图注反而啰嗦；需要说明时再补一句（引用官方图时要另起一行写来源）。
- **外部素材必须署名**：图库照片、他人截图、官方素材，在图注后另起一行：

  ```html
  <p style="font-size: 13px; line-height: 1.7; color: #6B7280; margin: 0 0 22px; text-align: center;"
     >图片：作者／来源 · 许可 · 原始链接</p>
  ```

- **比例**：清单与选型类同一期配图比例保持一致（常用 16:9 → 1080×608）；手册类以官方截图和场景照片为主，
  比例按内容裁即可，但要在项目根目录的 `qa_config.json` 里写 `{"image_ratio": "loose"}`，否则自检会报"比例不一致"。
- **图文比**：对标账号是 **6.2 张 / 千字**，换算下来**每 2–3 段就有一张图**——这是长文能读下去的关键，
  读者几乎不用连续读超过 5 段。我们的底线是 **≥2 张/千字**（`qa.py` 会报警），
  目标值 4 张/千字以上。**先按这个密度排图，再回头删字**，不要写完文字再补图。
- **体积**：单张 16:9 代码配图 ≈400KB；**照片底图一律输出 `.jpg`**（封面 ≈100–180KB、配图 ≈60–150KB）；
  合计 ≤3MB，官方截图密集的手册稿可以放宽到 5MB（`{"max_total_mb": 5}`）。截图先裁掉无关区域再放。
- **封面**：两张都要出，且都用素材照片做底——1276×544 用大字报两行标题，543×544 用三行短句；
  排版规则见 `visual-recipes.md` 第三节，色板从同一张照片里取。
- 截图上的红框、箭头这类标注直接画进图片里（用代码或截图工具），不要靠正文描述"图里第三个按钮"。
- 封面两张：1276×544（2.35:1）与 543×544（1:1）。方图单独排版，不要裁大图。

## 三、字体族

**正文一律不声明 `font-family`。** 微信端会用自己的默认字体，声明了反而在不同机型上不一致；尾部同理。

副作用：本地浏览器打开预览时，正文会落到浏览器默认字体（中文常见是宋体），看着和手机不一样。解决办法是在**预览外壳 CSS** 里补一套字体——外壳在复制范围之外，不会带进公众号：

```css
/* 只在本地预览生效，复制进公众号时不要带上这段 CSS */
#stage, #stage * { font-family: "Microsoft YaHei", "PingFang SC", "Noto Sans SC", system-ui, sans-serif; }
```

## 四、两处容易踩的细节

1. **含命令或大段英文的段落不要两端对齐。** `text-align: justify` 在纯中文段落上很整齐，
   但只要段落里出现较长的西文串（URL、英文句子、包名），它就会把西文之间的空格拉开成大缝，
   中文也会被挤成「官 方 描 述 是」这种散字。`md2wechat.py` 会**自动判断**并给这类段落换成左对齐
   （`needs_left_align()`）：含行内代码、含 ≥18 个连续 ASCII 字符、或整段 ASCII 占比 >35%，
   任一成立就左对齐。写稿时不用手动处理。
2. **长地址必须能断行。** 正文与列表样式里带上 `overflow-wrap: anywhere; word-break: break-word;`：前者参与最小宽度计算，缺少它时一条长 URL 会把整页在手机上撑宽（`break-word` 单独用不够，它不影响内在尺寸）。

## 五、转 HTML 与粘贴

```bash
python _工作文件/md2wechat.py 发布稿.md 公众号粘贴版.html
```

- 生成的文件里，`<!-- ===== 从这里开始，整段复制进公众号编辑器 ===== -->` 与 `<!-- ===== 复制范围到此结束 ===== -->` 之间才是要复制的内容；外面的 `<style>` 是本地预览外壳。
- 浏览器打开 → 全选复制 → 粘进公众号编辑器，行内样式会带过去。
- 同一份 Markdown 可直接分发到知乎、百家号、今日头条，图片按当期统一比例上传。

## 七、排版层面的去 AI 腔

版式固定，但**排布方式一模板化就会露馅**。下面几条和 `writing-craft.md` 配套，写稿排版时一起过：

- **别让整篇都是字段块。** 一个技能用四个加粗字段排完，是清单的骨架；但连着三四个技能一字不变地平铺，读者会开始跳读。每两三个技能之间插一句普通段落（过渡、取舍或一句吐槽），把节奏断开。
- **同一节里字段块最多两个。** 一节出现三个以上技能时，第三个改成叙述段落写：先说场景，再把安装命令写进句子里。
- **小标题别写成对偶排比。** 「要什么、为什么、怎么办」这种三连一眼是模板；用一句人话就行（例：把片子的四个工位拆开看）。
- **图注不要同一个句式用到底。** 六张配图如果都以"这张图展示了……"开头，等于没写图注。允许口语，但每张只说一件事。
- **段落不要等长。** 连续三段字数接近（机器会拦），就拆出一句 4–10 字的短句换气。
- **列表少用。** 正文里的 `<ul>` 全篇最多两处；能用一句话讲清的不要列成三条。
- **标点克制。** 破折号「——」全篇 ≤3 处、感叹号 ≤2 处；正文与图注都不放 emoji。
- **加粗只留真的重点。** 加粗色是墨绿，全篇只有一个强调色，用多了就不叫重点了。
