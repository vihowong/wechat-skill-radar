# 出图配方

**封面与配图一律以公开可商用的图片素材为底**：素材照片做背景，文字与图形用代码压上去。
三张图各有分工——装饰类用照片底（封面、章节图、氛围图），证据类用官方图（界面、文档截图），
信息类用代码画（对照表、流程、数据图，这类靠照片反而看不清）。
基础件在 `scripts/design_kit.py`：取色、对比度校验、大字报封面、配图画框、照片底图、色板与图形件。

## 一、素材从哪来

1. **可商用照片（默认，做封面与配图的底图）**——用 `scripts/stock_photos.py` 自己搜、自己挑：

   ```bash
   python _工作文件/stock_photos.py search --theme cyberpunk --top 8 --min-width 1200
   python _工作文件/stock_photos.py search "server room dark blue" --top 8 --min-width 1200
   python _工作文件/stock_photos.py pick 3 --used-in 封面
   python _工作文件/stock_photos.py record --file 素材/图库/我的截图.png \
       --source "自测截图" --license "自有" --author "本人" --used-in 配图2
   ```

   `--source` 默认 `auto`：有 `PEXELS_API_KEY` / `UNSPLASH_ACCESS_KEY` 就优先用它们（画质最好），
   否则用 Openverse，失败会自动退到 Wikimedia Commons（无需密钥）。
   下载会自动写入 `素材/图库/图片来源.md`；**正文用到 `素材/图库/` 的图时，`qa.py` 会检查这份记录**。
2. **官方图（证据类）**——README、官方文档、发布页里的界面图。引用要注明来源，裁掉无关区域但保留署名与水印，
   可以加红框引导，不能遮挡原信息、不能拼成误导性画面。
3. **代码画的图形（信息类）**——对照表、流程条、数据对比这类需要精确对齐的图，直接用 `design_kit` 的基础件画，
   或画在半透明面板上再叠到照片底上。

**禁止**：CC BY-NC / CC BY-ND 及任何"仅限非商业""不可修改"的素材；带大 logo、水印、真人面部特写的商业图库图；
来源不明的图。理由与署名格式见 `compliance.md`。

## 二、题材：科技 / AI / 赛博朋克

素材必须落在**科技、人工智能、赛博朋克、AI 领域**这条线上——办公室绿植、咖啡杯、握手、家居暖光这类
"通用商务风"一律不用，它们会把科技号写成企业内刊。

| `--theme` | 关键词（都是英文检索） | 适合 |
| --- | --- | --- |
| `tech` | data center servers / server room lights / circuit board macro / technology abstract dark | 通用科技底图 |
| `ai` | artificial intelligence abstract / neural network visualization / ai chip processor / robot hand technology | AI 方向、模型与算力 |
| `cyberpunk` | cyberpunk city night neon / neon lights dark street / futuristic city rain / hologram neon abstract | 封面首选，最适合压大字 |
| `code` | programming code screen dark / developer workspace night / terminal screen closeup | 编程、Agent、插件 |
| `robot` | robot arm industry / humanoid robot / drone technology | 机器人、自动化、具身智能 |
| `data` | data visualization screen / dashboard screen dark / charts monitor glow | 选型指南、数据类文章 |
| `abstract` | abstract dark gradient texture / digital particles dark / network nodes dark | 概念抽象、通用底图 |

哪个源找什么：

- **概念与氛围**（"人工智能""赛博朋克"这类抽象概念）→ Openverse、Pexels、Unsplash 命中好。
- **具体物体与场景**（机房、机器人、代码屏）→ Commons 也很稳，而且许可与作者信息更全。
- 一组关键词搜不到 3 张能用的，就换 `--theme`、换来源，或加更具体的词（"server rack blue light"）。

**选图五条标准**（挑图时逐条过，别只看缩略图好看）：

1. **暗调为主**：中低亮度、有明确暗部，压暗后还能留住细节。
2. **有留白**：至少一侧或一块区域是干净的（天空、墙面、虚化背景），留给大字。
3. **没有文字物体**：招牌、路牌、屏幕文字会和标题打架——霓虹光带可以，成串的字不行。
4. **横向或方形构图**，主体不压边；封面建议 ≥1600px 宽。
5. **不是疑似 AI 生成的实拍替代品**：列表里标 `⚠AI` 的是疑似 AI 生成素材（Openverse / Commons 上不少），
   可以用，但发布时要在图注或文末标「本图由 AI 生成」，别让它冒充实拍。

**题材与框架的搭配**：项目手册用"工作台 / 机房 / 代码屏"这类场景图；科普解读用抽象概念图；
选型指南用数据屏幕类；清单合集用暗调抽象底图。一期之内底图风格要统一（都是夜景霓虹，或都是冷调机房）。

## 三、大字报封面：串联排版

列表页里封面只有拇指大，所以封面靠**大字 + 强对比**取胜，不靠信息量。版式就用 `poster_cover_page`：

```python
dk.use_palette_from_photo("素材/图库/xxx.jpg")        # 先从素材取色（见第四节）
cover = dk.poster_cover_page(
    1276, 544, "../../素材/图库/xxx.jpg",
    title="装它只要一条命令\n但要先有 Node",     # \n 分行，每行 4–7 字
    hi_words=["一条命令", "Node"],                # 要点亮的词，最多两处
    kicker="项目手册 · 10 分钟上手",              # 标题上方一行小标签
    subtitle="从零到跑通第一步，附三条常用命令",   # 一行副标题
    tags=["官方文档", "门槛 ●●○", "2026-10-10"],  # 一行关键词，渲染成 A · B · C
    footer_left="GITHUB · README / DOCS SNAPSHOT",
    brand_line="● 你的skill好友",                # 账号锚点，位置不要动
)
```

完整的、可直接改文案就跑的模板在 `examples/make_pages_demo.py`（封面两种尺寸 + 照片底配图 + 代码信息图）：
复制成 `_工作文件/make_pages.py`，替换素材路径与文字即可。

排版规则（做出来才像"大字报"而不像 PPT）：

- **每行 4–7 字、2–4 行**。字越长字号越小（脚本会自动适配），所以短句才有冲击力。
- **串联**：字与字之间默认用一个小圆点串起来（`chain=True`）；左侧一条竖线穿过各行，每行一个节点（`rail=True`），
  形成一条从上到下的阅读动线。
- **阶梯**：后面每一行相对上一行右移（`stair=0.14`，相对字号），避免齐头排的死板。
- **只点亮两处**：`hi_words` 最多两个词，用主色 + 微发光。第三处开始就没有重点了。
  主色偏浅（跟白色几乎分不出）时，把 `hi_color` 传成点缀色，让重点跳出来。
- **背景必须压暗**：`dark=0.80` 起步，画面很花就 0.85；`blur=2.5` 柔化背景，让大字跳出来。
- **主标题与外层标题分工**：外层标题（公众号标题）说"给谁看/能拿到什么"，封面主标题说另一件事，别重复。
- **两个尺寸各自排版**：2.35:1 用两行长句；1:1 用三行短句（`title="装它只要\n一条命令"`），字号会自动变小。

**三条禁忌**：整屏都是字（没有照片呼吸感）；每行超过 7 字（缩到看不清）；一行里点亮三处以上（没有重点）。

## 四、配色逻辑：先取色，再校准，最后体检

配色不靠感觉，按三步走，出来的东西"有逻辑"且"看得清"：

**第一步：从素材照片取色。** 底色跟着照片走，画面才不打架：

```python
pal = dk.palette_from_photo("素材/图库/xxx.jpg")   # deep/navy/mid/base/base_l/mint/mint_hi/mint_d/orange
dk.use_palette(**pal)                              # 或一步到位：dk.use_palette_from_photo(path)
print(pal)
```

它的逻辑：底色阶取照片里占比最高那一族的色相（同源，不打架）；主色取照片里最有存在感的饱和色；
点缀色取画面里的第二色相，没有就用主色的互补色。

**第二步：明度校准。** `palette_from_photo` 会自动把主色、提亮色、点缀色推到目标对比度——
色相照照片走，明度按可读性推。手改色值时也用 `dk.ensure_contrast(色值, 底色, 4.5)` 过一遍。

**第三步：体检。** 交付前跑一次，两端底色都要过：

```python
dk.contrast_report()      # 分别打印 DEEP 与 BASE_L 上的对比度
```

- 大字标题 ≥3.0:1，正文/图注小字 ≥4.5:1。
- 报告里出现"偏弱"就换色值，别硬上。

**配色规则（人体视觉审美的几条硬约束）**：

1. **色相不超过两个**：底色一族（含照片） + 一个主色；点缀色只是主色的补充，不算第三色相。
2. **冷暖不打架**：照片是暖调（霓虹橙红）主色就用暖色，照片是冷调（机房蓝）主色就用冷色；
   强制给暖照片配冷主色会很脏。
3. **同屏不同时出现两个高饱和色**：主色管重点（数字、标题里被点亮的词、图表主线），点缀只管极小面积（节点、警示）。
4. **明度阶梯**：照片压暗后的底色最暗 → 标题最亮 → 主色介于两者之间；这样文字永远"浮"在画面上。
5. **60 / 30 / 10**：照片与深底约 60%，底色阶与面板约 30%，主色与点缀约 10%。
6. **一期一套**：封面和所有配图共用同一套色板（都从同一张或同风格的照片取色），别一张一套。

没有合适的素材照片可取样时，退回下面五套备好的基调（第八节）。

## 五、照片做底怎么排

- **封面**：`poster_cover_page(..., focus="left")`——左重右轻地压暗，左边放标题，右边留出照片的质感。
- **配图**：`figure_page(..., photo=..., focus="uniform")`——整屏均匀压暗（默认 `dark=0.78`、`blur=2.0`），
  因为配图的文字和图形铺满整张，必须哪儿都能读。
- **文字要有一块"自己的地方"**：照片上放段落文字时，套一个半透明深色面板（`dk.panel(..., fill="rgba(8,12,18,.62)")`），
  别直接压在照片上。
- **一张图只用一处照片**，其余交给代码画的图形件。
- **一律输出 JPEG**（照片底图存 PNG 会从 150KB 涨到 700KB）：

  ```bash
  python _工作文件/render.py _工作文件/pages/cover-2x1.html 封面/封面_1276x544.jpg \
      --width 1276 --height 544 --quality 86
  ```

## 六、构图

- **封面**：大字标"压"进画面里（左侧或中部），不要做成"上面标题、下面一张图"的三段式；
  标题里的关键数字或关键词单独点亮，和画面里的光点呼应。
- **结构线**：封面可以带一条结构线（时间轴 / 进度尺 / 流程条），让读者在封面就看出这篇按什么切。
- **配图**：一期内的多张图用**不同骨架**（看板 / 对照 / 管线 / 阶梯 / 漏斗 / 双栏 / 矩阵），
  统一的是页眉角标、色板和页脚。
- **文字精简**：一张图说一件事；能用图标和箭头说明的，不要写整段文字。最小的字控制在画布宽度的 1% 左右
  （1080 宽的图画 10–13px 字）。
- **配图承担"可视化"而不是"装饰"**：阈值、对比、流程、分布这类，能用一张图说清就别写三段话。

## 七、体积预算

| 项目 | 建议 |
| --- | --- |
| 单张照片底封面 | ≈100–180KB（JPEG，`--quality 86`） |
| 单张照片底配图 | ≈60–150KB（JPEG） |
| 单张代码配图（无照片） | ≈400KB（PNG） |
| 正文配图合计 | ≤3MB；官方截图很多的手册稿可以放宽到 5MB（`qa_config.json` 写 `max_total_mb`） |
| 渲染尺寸 | 1080×608（配图）／1276×544（封面）／543×544（方图） |

照片降体积：先 `--max-width 1600` 缩到够用，再压暗存 JPEG；截图先裁掉无关区域。
点阵放稀（间距 34 而不是 22），少叠发光。

## 八、必须避开的坑（都实际踩过）

1. **照片底图输出 PNG。** 同一张封面 PNG 734KB、JPEG 99KB；照片页面一律出 `.jpg`。
2. **压暗不够，标题糊在照片上。** `dark` 调到 0.80+，再不行加 `blur`；别靠描边救。
3. **选了带文字的素材。** 招牌、路牌、屏幕上的字会和标题打架——选图时就要避开。
4. **暖照片配冷主色。** 主色从照片里取（`palette_from_photo`），不要手动硬塞一个蓝。
5. **f-string 里嵌套的字符串不会被替换。** `f"...{svg(txt(0, 0, \"{code}\"))}..."` 里的 `{code}` 会原样印出。
   先把变量算好、拼好，再放进 f-string。
6. **水平或垂直的细线加模糊滤镜会整条消失。** 直线的包围盒高度是 0，`feGaussianBlur` 的滤镜区域随之变成 0。
   线条发光改用 `style="filter:drop-shadow(0 0 7px 色值)"`。
7. **箭头要记得带定义。** `marker-end="url(#ar0)"` 依赖同一个 SVG 里的 `<marker>`；配图是单独一层 SVG，
   必须把 `arrow_defs()` 一起传进去，否则箭头不显示（而且不报错）。

## 九、无头渲染

```bash
python _工作文件/render.py _工作文件/pages/cover-2x1.html 封面/封面_1276x544.jpg --width 1276 --height 544
python _工作文件/render.py _工作文件/pages/fig1.html 配图/配图1_xxx.jpg --width 1080 --height 608
```

- 依赖本机 Chrome 或 Edge，脚本会自动找常见安装路径，也可以用 `--browser` 指定。
- 输出后缀写 `.jpg` 就转成 JPEG（需要 Pillow）；照片页面必须这么出。
- **无头浏览器的窗口有最小宽度（约 500px）**：`--width` 小于 500 时截图会被裁掉右侧，
  看起来像"版面溢出"，其实是视口限制。要出手机宽度预览，渲染 505 宽再裁中间 375px。
- 渲染完**逐张目视**：标题有没有被照片里的高亮细节压住、大字有没有被裁、底部信息栏有没有出汗、
  四种色阶（底色/白/主色/点缀）在同一张里是否协调。

## 十、一期一套色板

正文版式的颜色是固定的（见 `wechat-layout.md`，`qa.py` 会检查白名单）；**封面与配图的色板每期换一套**——
默认从当期素材照片取色（第四节）。没有合适照片时，退回这五套备好的基调：

| 基调 | 底色渐变两端 | 主色 / 提亮 | 点缀色 |
| --- | --- | --- | --- |
| 墨绿松石（账号默认） | `#060E18 → #245448` | `#3AC98F` / `#5CD971` | `#FF7A59` |
| 深蓝电光 | `#070F1E → #1E3A6E` | `#4FA8FF` / `#7CC2FF` | `#FFD166` |
| 紫青霓虹 | `#0B0A1A → #3A2A64` | `#8B7CF6` / `#A99BFF` | `#3AD8C8` |
| 石墨橙 | `#0E1116 → #4A3126` | `#FF9A3C` / `#FFB865` | `#5CD971` |
| 靛青薄荷 | `#07131A → #173C4A` | `#2FD3C0` / `#5CE6D6` | `#FF7A59` |

```python
dk.use_palette(DEEP="#0B0A1A", NAVY="#1B1436", MID="#2A1F53",
               BASE="#3A2A64", BASE_L="#4B3A7A",
               MINT="#8B7CF6", MINT_HI="#A99BFF", MINT_D="#5B4BC4", ORANGE="#3AD8C8")
```

**换色板可以，换风格不行。** 下面三个锚点每期都不动：

1. **账号锚点**：封面右下角始终是「你的skill好友」小字 + 薄荷小圆点；正文配图不出现账号名、二维码、联系方式。
2. **明暗锚点**：一律深色底 + 亮色主色，主色只给标题点亮、图表主线条、数字、强调块；
   浅底卡片一屏最多出现一次（放"结论"那种）。
3. **信息骨架锚点**：封面固定五件套——kicker 小标签、两行大标题、副标题、一行关键词、右下角账号小字；
   每期只换**照片**、**色板**和**结构图形**，这五件套的位置关系不动。

另外两条经验：

- **一期内部必须成体系**：封面和所有配图共用同一套色板与同一种图形语言，别一张一套。
- **对比度优先于好看**：出现两个以上大面积高饱和色同屏时，回到明度层级重排——照片压暗一层、主色降一档。
